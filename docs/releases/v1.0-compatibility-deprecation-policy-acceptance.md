## 2. Accepted Contract

The accepted release-series governance is:

``` text
1.0.x → compatibility-preserving fixes
1.x   → backward-compatible evolution
2.0   → intentional breaking Stable-contract changes
```

The policy also establishes:

- behavioral, not merely import-level, compatibility review;
- distinct Stable / Candidate / Experimental / Internal / Deferred
  obligations;
- Deprecated Stable as a still-functional compatibility state;
- normal Stable removal no earlier than the next major version;
- mandatory deprecation records and migration guidance;
- EN/zh-TW functional parity for user-facing migration guidance;
- documentation and CHANGELOG obligations;
- explicit emergency compatibility-exception evidence;
- compatibility-sensitive Code Review requirements;
- continued authority of the Step 8.2 public-contract freeze tests.

Step 8.6 does not redefine the frozen Stable surface, create Step 8.7
support claims, or pre-empt Step 8.8 release automation.
