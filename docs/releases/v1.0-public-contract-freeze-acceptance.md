## 1. Purpose

This document records the acceptance boundary for Step 8.2.

Step 8.2 exists to turn the accumulated OpenProjectLab implementation
surface into an intentional v1.0 compatibility promise. It does not
declare every importable object, historical behavior, architecture
proposal, or deferred capability Stable.

The governing rule is:

``` text
Implemented
    ≠
Public
    ≠
Stable

Stable
    =
Intentional + Tested + Documented + Maintainable
```

## 4. Final Contract Classification

### Stable --- verified v1.0 subset

-   narrow `generator.sdk` public façade;
-   canonical Generator lifecycle and reviewed request/plan/result
    semantics;
-   `openprojectlab.generators` Plugin Entry Point identity;
-   reviewed Plugin validation and registration behavior;
-   reviewed CLI command surface;
-   Course / Week Domain;
-   built-in Generator identities;
-   reviewed canonical artifact layouts;
-   Courseware Composition behavior;
-   provider-independent AI public boundary;
-   reviewed Marketplace
    artifact/repository/acquisition/integrity/installation/ Template
    Package contracts;
-   implemented Configuration subset;
-   implemented Filesystem-visible subset;
-   public error hierarchy and reviewed structured validation fields;
-   distribution identity and canonical console entry point.

"Stable subset" means only behavior demonstrated by implementation and
freeze tests is promised.

### Experimental

-   live AI provider verification;
-   provider-specific operational behavior requiring network,
    credentials, external availability, timeout policy, or paid
    invocation.

### Internal

-   private helpers;
-   parser internals;
-   registry internals;
-   adapter-private provider SDK types;
-   filesystem internals beyond the verified public semantics;
-   undocumented template implementation details;
-   unrelated internal test helpers.

### Deferred

Deferred AI, Marketplace, filesystem-transaction, signing/trust,
dependency resolution, remote service, streaming/tool-calling, AI
CLI/refactoring, and other v1.1+ capabilities remain outside the v1.0
compatibility promise.

## 5. Packaging Finding

Step 8.2 identified a release-readiness risk that belongs to Step 8.4:

> Repository-level `templates/` are not yet proven to be available from
> the built release artifact and a clean installation.

Therefore Step 8.2 freezes only the packaging metadata subset that is
currently verified, including:

``` text
distribution: openprojectlab
Python: >=3.12
console script: opl = generator.cli.main:main
reviewed runtime dependencies
generator package discovery
```

Step 8.2 does **not** claim that Generator templates/resources are
release-ready inside a wheel.

Step 8.4 must:

``` text
build artifact
    ↓
install into clean environment
    ↓
verify opl
    ↓
verify packaged templates/resources
    ↓
run representative installed-user workflow
```

If required templates/resources are missing, that is a v1.0 packaging
blocker.
