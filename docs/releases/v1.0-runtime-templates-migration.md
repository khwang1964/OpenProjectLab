# Step 8.4 Runtime Templates Migration Plan

## Decision

`generator/resources/templates/` becomes the single canonical runtime template
source for source-checkout and installed-wheel execution.

The legacy repository-level `templates/` tree is migrated, verified byte-for-byte,
then removed. OpenProjectLab must not maintain two independent canonical template
trees.

## Automated Sequence

```powershell
python scripts\migrate_runtime_templates.py
python scripts\apply_step84_package_resources.py

python -m pytest `
  tests\template `
  tests\packaging\test_v1_installed_resources_contract.py `
  -v --no-cov
```

After the copied tree is verified and source/template regression is green:

```powershell
python scripts\migrate_runtime_templates.py --remove-source
```

Because `generator/resources/templates/` already contains the verified copy, the
second command removes only the legacy repository-level root.

Then:

```powershell
git status
git diff --check
```

Git should normally detect most template files as renames during review.

## Package Configuration

`pyproject.toml` declares:

```toml
[tool.setuptools.package-data]
"generator.resources" = [
    "templates/**/*",
]
```

Top-level `templates` remains excluded from Python package discovery. Runtime
resources are package data under `generator.resources`, not a standalone Python
package.

## CLI Resolution

The CLI preserves explicit `--template-root` and configuration overrides.

Only the default changes:

```text
before:
PROJECT_ROOT / "templates"

after:
package_template_root()
```

This removes installed-wheel dependence on the source repository.
