# v1.3.3 Release Evidence Verification Orchestration — Design Baseline

> Status: Proposed / Pending design review

## Purpose

Define the application-layer contract that composes the accepted v1.3.1 validation
core and v1.3.2 read-only adapters into one deterministic, fail-closed verification
workflow.

## In scope

- explicit immutable verification request
- injected repository and GitHub observation boundaries
- deterministic identity and lifecycle consistency composition
- reuse of `ReleaseEvidenceValidator`
- immutable report with stable findings
- structured collection, contradiction, and validation failure distinctions
- caller-supplied focused-test evidence

## Out of scope

- production implementation
- running pytest or coverage
- Git or GitHub mutations
- merge, tag, release, artifact, or publication operations
- CLI or public SDK exposure
- retries, polling, persistence, caching, and credential handling

## Acceptance gates

- Architecture and release baseline agree.
- Roadmap, HISTORY, and CHANGELOG expose one Design First proposal.
- Design-contract tests protect the accepted and deferred boundaries.
- Focused design verification passes.
- Pre-commit and required CI pass.
- Design PR merge and synchronized-main verification remain pending.
- Separate terminal design acceptance remains pending.
