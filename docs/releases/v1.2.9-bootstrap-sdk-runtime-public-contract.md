# OpenProjectLab v1.2.9 Bootstrap SDK Runtime Public Contract

> **Status:** Accepted --- Terminally Closed
> **Predecessor:** v1.2.8 Bootstrap CLI Public Contract Stabilization --- Accepted

## Goal

Define a stable Python SDK adapter for the accepted bootstrap runtime without changing
the existing generator/plugin SDK surface or importing command-line process semantics.

## Public surface

The proposed import path is `generator.sdk.bootstrap_runtime`.

```text
BootstrapSdkRequest
BootstrapSdkResult
BootstrapSdkMode
BootstrapSdkUsageError
BootstrapSdkExecutionError
run_bootstrap
```

Existing `generator.sdk` generator and plugin exports remain source compatible.
The new bootstrap names are additive and are not re-exported from `generator.sdk`
until the implementation slice explicitly accepts that compatibility decision.

## Modes and lifecycle

```text
preview
apply
apply-and-validate
```

The SDK delegates to the same core planning, apply, and validation lifecycle used by
the CLI adapter. Preview never mutates. Apply is the only mutation phase.
Apply-and-validate performs validation after a successful apply.

Requests, results, findings, and phase evidence are immutable. Operation, finding,
and evidence ordering is deterministic for identical inputs.

## Failure taxonomy

Invalid SDK input raises `BootstrapSdkUsageError` before runtime execution.
Runtime or check execution failure raises `BootstrapSdkExecutionError` and fails closed
while preserving phase identity, failed check identity, and already completed evidence.
Validation findings are represented by a normal `BootstrapSdkResult` whose validation
state is invalid; findings are not translated into operational exceptions.

## Library semantics

`run_bootstrap` returns a typed result. The SDK must not write to stdout or stderr and
must not expose or derive process exit codes. Callers own rendering and process policy.

The SDK must not import the CLI adapter, and the CLI adapter must not import the SDK.
Both are sibling adapters over the core bootstrap runtime.

Validation must not call apply, must not repair filesystem state, and must not trigger
rollback, hidden retry, or compensating mutation.

## Deferred boundaries

The following remain deferred: JSON serialization and schema guarantees, asynchronous
or concurrent execution, remote execution, plugin-provided validation checks, automatic
repair, retry or rollback policy, and a public bootstrap extension protocol.
