# v1.3.8-v1.3.10 Verification Request Usability and Stable CLI Design Train

> Status: Design Accepted / Completed

## Train scope

- v1.3.8 — canonical serialization of the accepted immutable verification request
- v1.3.9 — deterministic offline request validation and inspection
- v1.3.10 — stable `release-evidence` CLI public contract and documentation parity

## Dependency order

v1.3.8 defines canonical request output. v1.3.9 composes strict decoding and canonical
encoding without runtime authority. v1.3.10 promotes the already accepted verification
preview together with offline validation as one stable additive CLI family.

## Delivery plan

The three adjacent capabilities share one Design PR, one terminal Design Acceptance
PR, one implementation PR, one pending terminal-alignment PR, and one separate final
acceptance closure PR. Explicit merge authorization remains required at every PR gate.

## Non-goals

- no production implementation in the Design Train
- no SDK, HTTP, RPC, plugin, marketplace, or remote service
- no stdin, output file, batch, queue, watch, retry, polling, or scheduling
- no discovery, repair, enrichment, persistence, cache, telemetry, or credentials
- no test execution, arbitrary subprocess, mutation, release, or publication

## Code Review Checklist

- [ ] The three slice contracts compose without overlapping authority.
- [ ] v1.3.8 remains a pure deterministic model-to-document operation.
- [ ] v1.3.9 remains offline and cannot build or invoke a runtime.
- [ ] v1.3.10 preserves existing CLI behavior and the read-only allowlist.
- [ ] Stable status does not imply mutation or automatic evidence collection.
- [ ] Production implementation remains Not Started for every slice.
