## 3. Scope Presented for Acceptance

Acceptance review covers only the proposed deterministic local adapter:

- `opl marketplace versions IDENTITY --catalog FILE [--json]`;
- `opl marketplace inspect COORDINATE --catalog FILE [--json]`;
- `opl marketplace verify COORDINATE --catalog FILE --payload-root DIR
  [--json]`;
- `opl marketplace install COORDINATE --catalog FILE --payload-root DIR
  [--dry-run] [--json]`;
- exact `namespace/name@MAJOR.MINOR.PATCH` coordinates;
- UTF-8 local catalog schema version 1;
- safe payload-root containment and file-only acquisition;
- exact lookup, SHA-256 verification, and failure-before-installation;
- opt-in deterministic JSON and the preserved broad `0`/`2` exit contract;
- in-memory, non-activating, non-persistent installation semantics.

The existing Marketplace repository does not expose global enumeration, so
acceptance does not invent `opl marketplace list`.

## 4. Preserved and Deferred Boundaries

Throughout closure:

- the reviewed v1 command inventory remains unchanged;
- `marketplace` remains absent from the production parser;
- v1.1.4 Marketplace CLI Implementation remains Not Started;
- `versions`, `inspect`, `verify`, and `install --dry-run` do not install;
- failed lookup, acquisition, containment, or integrity leaves installer state
  unchanged;
- remote Marketplace access and implicit network fallback remain Deferred;
- persistence, activation, dependency resolution, signing/trust,
  ratings/reviews, and monetization remain Deferred;
- AI CLI Contract and implementation remain Not Started;
- Formal v1.1 Acceptance remains Not Accepted.

Contract acceptance authorizes later implementation work only under the
accepted boundary. It is not evidence that any proposed command exists in the
production parser.

## 6. Fail-closed Rules

Marketplace CLI Contract Acceptance must remain `Not Accepted` while any
required closure gate is Pending or failed. Blockers include:

- registration or implementation of `marketplace` during v1.1.3;
- removal or reinterpretation of an existing v1 command;
- invention of global repository enumeration;
- network fallback or unsafe payload resolution;
- installation before successful SHA-256 verification;
- claims of persistence, activation, dependency resolution, or trust;
- contradiction among the governing contract, this record, and trackers;
- failed focused, regression, coverage, quality, or required CI gates;
- an unmerged acceptance PR or unsynchronized main;
- missing post-merge verification or terminal alignment;
- fabricated test, coverage, PR, CI, commit, tag, or release evidence.
