# v1.3.5–v1.3.7 Read-only Verification Delivery Train

> Status: Proposed / Pending design review

## Train scope

- v1.3.5 — one stateless read-only verification invocation
- v1.3.6 — strict deterministic request and report I/O contracts
- v1.3.7 — one explicit opt-in read-only CLI preview

## Dependency order

v1.3.7 depends on v1.3.6 decoding and rendering. v1.3.6 serializes the immutable
request and report accepted by v1.3.5. v1.3.5 delegates to the accepted v1.3.4
runtime. Later capabilities cannot expand an earlier capability's authority.

## Shared boundaries

- caller-supplied exact evidence
- deterministic fail-closed processing
- no arbitrary subprocess or test execution
- no Git/GitHub mutation, release, publication, persistence, or credential prompt
- production implementation remains Not Started for all three capabilities

## Train acceptance strategy

One Design PR and one terminal Design Acceptance PR govern all three designs. One
implementation PR delivers the accepted train. The strict pending-alignment and
separate-closure PR pair remains required for final implementation acceptance.
