# v1.3.4 Read-only Verification Runtime Wiring — Design Baseline

> Status: Accepted / Completed

## Purpose

Define the minimum internal runtime composition boundary that makes the accepted
v1.3.1–v1.3.3 release-evidence components constructible without expanding their
read-only authority.

## In scope

- immutable explicit runtime configuration
- deterministic `ReadCommand` implementation
- exact Git and GitHub read-command allowlist
- explicit working directory, timeout, and environment boundary
- stable execution-failure mapping
- internal factory wiring accepted adapters, validator, and orchestrator
- deterministic fake-based contract tests

## Out of scope

- production implementation
- CLI or public SDK
- running verification automatically
- pytest, coverage, or arbitrary subprocess execution
- Git/GitHub mutation, merge, tag, release, or publication
- retry, polling, persistence, caching, telemetry, and credentials
