## 3. Scope Accepted for Review

Acceptance review covers:

- preservation of the reviewed v1 command inventory and installed `opl`
  entry point;
- additive evolution and compatibility/deprecation governance;
- reservation of `opl marketplace ...` and `opl ai ...` for later contracts;
- broad exit behavior, stdout/stderr, and machine-readable-output boundaries;
- validation-before-side-effect and dry-run rules;
- deterministic local Marketplace and provider-independent AI boundaries;
- bilingual documentation and installed-artifact verification obligations.

It does not accept or implement either reserved command family.

## 4. Preserved Boundaries

Throughout closure:

- all reviewed v1 command lines remain valid;
- `marketplace` and `ai` remain absent from the production parser;
- Marketplace CLI Contract and implementation remain Not Started;
- AI CLI Contract and implementation remain Not Started;
- remote Marketplace and automatic activation remain Deferred;
- live AI remains Experimental and opt-in;
- no production `--json` schema or finer Stable exit taxonomy is overclaimed;
- Formal v1.1 Acceptance remains Not Accepted.

## 6. Fail-closed Rules

Formal v1.1 CLI Public Contract Acceptance must remain `Not Accepted` while
any required closure gate is Pending or failed. Blockers include:

- weakening or replacing the v1 command inventory;
- premature registration or implementation of `marketplace` or `ai`;
- claiming a Stable JSON schema or exit taxonomy without accepted evidence;
- contradiction among the governing design, this record, and trackers;
- failed focused, regression, coverage, quality, or required CI gates;
- unmerged acceptance PR or unsynchronized main;
- missing post-merge verification or terminal alignment;
- fabricated test, coverage, PR, CI, commit, tag, or release evidence.
