# OpenProjectLab v1.2.7 Bootstrap CLI/runtime Wiring

> **Status:** Accepted --- Terminally Closed
> **Predecessor:** v1.2.6 Bootstrap Runtime Integration --- Accepted / Completed
> **Production CLI Wiring:** Not Started

## Purpose

Define an explicit experimental adapter from the canonical Bootstrap CLI to the
accepted internal runtime coordinator without changing legacy Bootstrap behavior
or registering a second CLI surface.

## Canonical Boundary

``` text
Canonical console entrypoint --- generator.cli.main:main
Canonical parser --- generator.cli.main.build_parser
Canonical Bootstrap handler --- generator.cli.main._handle_bootstrap
generator.main legacy parser registration --- Forbidden
Public SDK expansion --- Forbidden
```

## Compatibility Contract

The existing `opl bootstrap PROJECT_SLUG --name NAME` grammar, output-root,
`--dry-run`, and `--force` behavior remain authoritative when experimental
runtime wiring is not explicitly selected.

``` text
No experimental opt-in --- Existing BootstrapGenerator path unchanged
Experimental opt-in + --dry-run --- BootstrapRuntimeMode.PREVIEW
Experimental opt-in, no --dry-run --- BootstrapRuntimeMode.APPLY
Experimental validation opt-in --- BootstrapRuntimeMode.APPLY_AND_VALIDATE
Implicit validation --- Forbidden
Experimental failure fallback to legacy path --- Forbidden
```

The implementation slice must choose stable, machine-verifiable option spelling
only after parser collision tests. Experimental options must fail closed when
dependencies or validation configuration are unavailable.

## Adapter Responsibilities

- translate existing normalized CLI arguments into one immutable runtime request;
- inject planner, dry-run, apply, and validation dependencies explicitly;
- call `BootstrapRuntimeCoordinator.execute(request)` exactly once;
- preserve existing exit-code, stdout/stderr, output-root, dry-run, and force
  contracts where their semantics already exist;
- keep runtime models internal and avoid serialized public SDK commitments.

``` text
Coordinator call --- BootstrapRuntimeCoordinator.execute(request) exactly once
```

## Failure Semantics

``` text
Argument / opt-in conflict --- Parser or adapter error / no execution
Missing runtime dependency --- Fail Closed / no legacy fallback
Planning failure --- Existing typed failure propagated
Apply failure --- Existing partial evidence preserved
Validation execution failure --- Existing typed failure propagated
Invalid validation result --- Completed invalid result / non-success exit
Success-shaped partial CLI output --- Forbidden
```

## Code Review Checklist

- [ ] Only `generator.cli.main` receives parser/handler wiring.
