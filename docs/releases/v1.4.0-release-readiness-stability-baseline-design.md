# v1.4.0 Release Readiness Stability Baseline Design

> Status: Proposed / Pending design review

## Delivery slice

- Define the strict canonical release-readiness stability evidence snapshot.
- Define deterministic fail-closed stability evaluation and reason classifications.
- Define the stable bounded read-only readiness-evaluation CLI.

## Accepted predecessor

The design builds on the terminally accepted v1.3.29-v1.3.31 migration-chain
verification train and the accepted v1.3 platform contracts. It consumes accepted
evidence without weakening revision binding, deterministic verification, or the
offline read-only boundary.

## Proposed boundary

Evaluation binds one explicit repository revision to required CI, focused tests,
full regression, coverage, accepted audit-chain evidence, public support surfaces,
known limitations, and unresolved blockers. Missing or conflicting evidence cannot
establish readiness. Production implementation is Not Started.

## Deferred work

Version mutation, tag creation, artifact construction, signing, GitHub Release
creation, package publication, compatibility promotion, remote evidence collection,
network access, repair, rollback, and repository mutation remain deferred and require
separate design and explicit authorization.

## Review gates

- [ ] Architecture and release baseline agree on explicit revision-bound evidence.
- [ ] Snapshot parsing rejects ambiguity, unknown fields, and contradictory evidence.
- [ ] Evaluation has deterministic `READY`, `BLOCKED`, and `INDETERMINATE` outcomes.
- [ ] Missing, stale, or revision-mismatched evidence fails closed.
- [ ] Existing v1.3 public and compatibility boundaries remain unchanged.
- [ ] CLI input limits remain bounded, offline, read-only, and fail closed.
- [ ] Contract tests, roadmap, HISTORY, and CHANGELOG agree.
- [ ] Code Review Checklist covers architecture, tests, documentation, and safety.
- [ ] A separate terminal Design Acceptance follows merge verification.
