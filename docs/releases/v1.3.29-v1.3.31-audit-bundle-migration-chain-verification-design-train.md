# v1.3.29-v1.3.31 Audit Bundle Migration Chain Verification Design Train

> Status: Proposed / Pending design review

## Delivery train

- v1.3.29 defines the strict canonical migration-chain manifest.
- v1.3.30 defines deterministic offline chain verification.
- v1.3.31 defines the stable bounded read-only chain-verification CLI.

## Accepted predecessor

The train builds on the terminally accepted v1.3.26-v1.3.28 canonical migration
receipt, deterministic receipt verifier, and bounded read-only verification CLI.
It composes accepted receipt verification without weakening its fail-closed boundary.

## Proposed boundary

Verification binds an explicit ordered manifest, N receipt documents, and exactly
N+1 bundle documents into one continuous initial-to-final chain. It performs no
migration, repair, discovery, publication, or repository mutation.

## Deferred work

Signing, identity, authorization, trust, provenance, attestation, remote evidence,
network access, publication, rollback, repository mutation, and chain execution
remain deferred. Production implementation is Not Started.

## Review gates

- [ ] Architecture and release baseline agree on immutable ordered inputs.
- [ ] Manifest parsing rejects ambiguity, unknown fields, and malformed identities.
- [ ] Verification enforces counts, adjacency, continuity, and terminal bindings.
- [ ] Accepted single-receipt verification is reused for every chain edge.
- [ ] CLI count and byte limits remain bounded, offline, read-only, and fail closed.
- [ ] Contract tests, roadmap, HISTORY, and CHANGELOG agree.
- [ ] A separate terminal Design Acceptance follows merge verification.
