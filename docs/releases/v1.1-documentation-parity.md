## 1. Purpose

This slice establishes the release-level documentation parity contract for the
user-facing v1.1 surface.

Earlier slices already provide focused documentation automation for Marketplace
CLI and AI CLI. v1.1.7 does not replace those authorities. It coordinates them
with the existing bilingual User Manual structure, functional parity, and
First 15 Minutes / onboarding evidence.

## 3. Bilingual Documentation Contract

English and Traditional Chinese (Taiwan) manuals must preserve:

- the same top-level chapter set;
- the same Stable v1 command inventory;
- the same reviewed additive `marketplace` and `ai` families;
- the same Marketplace CLI command inventory;
- the same AI CLI command inventory;
- equivalent global options and shared write controls;
- equivalent Stable / Experimental classifications;
- equivalent stdout / stderr / exit-code failure semantics;
- equivalent non-mutating / no-partial-state claims where applicable;
- equivalent deferred-capability boundaries;
- equivalent onboarding / First 15 Minutes coverage.

Literal sentence translation is not required. Functional contract parity is.

## 5. Release-level Automation

`tests/documentation/test_v1_1_release_documentation_parity.py` must fail
closed on release-level drift.

It verifies:

- this governing design exists;
- v1.1.6 AI CLI Implementation is already Accepted;
- Formal v1.1 Acceptance remains Not Accepted;
- EN and zh-TW top-level chapter sets match;
- both CLI manuals contain `marketplace` and `ai`;
- both languages expose the exact Marketplace command inventory;
- both languages expose the exact AI command inventory;
- existing structural and functional parity authorities remain present;
- AI CLI parity automation remains present;
- onboarding / First 15 Minutes authorities remain present;
- v1.1.8 Reliability / Artifact-backed Verification remains the next release
  gate after v1.1.7 closure.

## 6. Explicit Non-goals

v1.1.7 does not:

- add runtime commands;
- change Marketplace or AI implementation behavior;
- promote Experimental AI provider behavior to Stable;
- introduce remote Marketplace behavior;
- add implicit provider, SDK, credential, or network fallback;
- claim unsupported environments;
- perform artifact-backed release verification;
- formally accept v1.1.

## 7. Acceptance Blockers

The slice is blocked by:

- EN-only or zh-TW-only user-facing command claims;
- missing Marketplace or AI CLI documentation in either locale;
- structural chapter drift;
- failure-semantic drift;
- Stable / Experimental classification drift;
- missing First 15 Minutes / onboarding authority;
- failed documentation regression;
- failed required CI;
- unsynchronized main after merge;
- missing post-merge consistency verification;
- any premature `Formal v1.1 Acceptance --- Accepted` state.
