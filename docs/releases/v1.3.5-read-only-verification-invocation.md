# v1.3.5 Read-only Verification Invocation Boundary — Design Baseline

> Status: Accepted / Completed

## Purpose

Define the minimum internal application-service boundary that performs one
caller-authorized read-only verification using the accepted v1.3.4 runtime.

## In scope

- internal `ReadOnlyVerificationInvoker` contract
- one immutable request per invocation
- exactly one delegation to the accepted orchestrator
- existing immutable report returned unchanged
- deterministic failure preservation
- invocation independence and absence of shared mutable state
- deterministic fake-based design-contract tests

## Out of scope

- production implementation
- CLI, public SDK, HTTP, RPC, plugin, or entry-point exposure
- evidence discovery, inference, repair, or enrichment
- pytest, coverage, or arbitrary subprocess execution
- retry, polling, batch, queue, cache, persistence, telemetry, or scheduling
- Git/GitHub mutation, merge, tag, release, publication, or document writes

## Acceptance gates

- Architecture and release baseline agree.

- Design-contract tests protect every accepted and deferred boundary.
- Focused design verification and pre-commit pass.
