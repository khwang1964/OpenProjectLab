# v1.4.1 Deterministic Readiness Snapshot Assembly Design

> Status: Proposed / Pending design review

## Delivery slice

- Define the strict canonical `ReadinessEvidenceManifest`.
- Define deterministic revision-bound local snapshot assembly.
- Define the bounded offline read-only assembly CLI.

## Accepted predecessor

The design consumes the terminally accepted v1.4.0 snapshot and evaluator contracts without
changing their schema, outcomes, support classifications, or release-authority boundary.

## Proposed boundary

Only explicitly named local evidence beneath one explicit input root may be assembled. Missing,
ambiguous, stale, conflicting, unsafe-path, or revision-mismatched evidence fails closed.
Production implementation is Not Started.

## Deferred work

Readiness evaluation, remote collection, Git/GitHub operations, credential lookup, version or
repository mutation, tags, artifacts, signing, publication, repair, and rollback remain separate
and require explicit design and authorization.

## Review gates

- [ ] Manifest and architecture define identical explicit inputs and limits.
- [ ] Path containment and symlink rejection are fail closed.
- [ ] All evidence is validated and bound to one revision.
- [ ] Assembly and canonical rendering are deterministic.
- [ ] CLI remains bounded, offline, and read-only.
- [ ] v1.4.0 evaluation and release authorization remain separate.
- [ ] Tests, roadmap, HISTORY, CHANGELOG, and checklist agree.
- [ ] A separate Design Acceptance closure follows merge verification.
