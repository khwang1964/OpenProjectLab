## Accepted design

- v1.3.29 defines a strict canonical migration-chain manifest with ordered receipt
  identities and explicit initial/final bundle digests.
- v1.3.30 defines deterministic offline verification of counts, receipt identities,
  adjacency, schema continuity, steps, plan fingerprints, and terminal bindings.
- v1.3.31 defines a bounded read-only chain-verification CLI with explicit file-count
  and aggregate-byte limits and no implicit discovery.
- Empty chains, malformed manifests, broken adjacency, reordered or duplicate
  receipts, cycles, unknown schemas, and ambiguous plans fail closed.
- Migration execution, repair, discovery, signing, identity, trust, provenance,
  attestation, network access, publication, and repository mutation remain out of scope.
