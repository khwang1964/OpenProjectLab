## 1. Purpose

This document defines the Design First contract for a deterministic,
mutation-free preview of an existing `BootstrapPlan`.

The preview makes the future execution order and expected effects inspectable
without instantiating or executing generators and without committing state.

``` text
BootstrapPlan
    ↓
BootstrapDryRunExecutor.preview(plan)
    ↓
BootstrapDryRunPreview
```

No production dry-run runtime is authorized by this document.

## 2. Scope

In scope:

- `BootstrapDryRunStep`;
- `BootstrapDryRunPreview`;
- `BootstrapDryRunExecutor`;
- reuse of the existing immutable `BootstrapPlan`;
- deterministic preview ordering;
- equivalent-preview behavior;
- descriptive projection of expected effects;
- fail-closed, zero-partial-state preview failure.

Out of scope:

- generator instantiation or execution;
- filesystem, manifest, backup, or checkpoint writes;
- apply execution;
- validation runtime;
- generalized rollback;
- checkpoint / resume;
- network access;
- plugin activation;
- Stable Bootstrap CLI syntax.

## 3. Core Contracts

### 3.1 BootstrapDryRunStep

`BootstrapDryRunStep` is an immutable, inspectable projection of one ordered
`BootstrapStep`. It contains the stable step identity, generator identity,
normalized inputs, and ordered expected effects required for preview.

It is descriptive data only. It must not instantiate or execute a generator
and must not expose an operation that commits an expected effect.

### 3.2 BootstrapDryRunPreview

`BootstrapDryRunPreview` is the immutable aggregate preview result. It
contains ordered `BootstrapDryRunStep` values and ordered expected effects
derived from the authoritative input plan.

The preview must preserve plan traceability without creating an alternative
plan, generator lifecycle, or mutation pipeline.

### 3.3 BootstrapDryRunExecutor

`BootstrapDryRunExecutor.preview(plan)` consumes an existing immutable
`BootstrapPlan` and returns a `BootstrapDryRunPreview`.

Its responsibility is limited to deterministic projection and inspection.
Despite the executor name, it does not execute generators or filesystem
operations in v1.2.3.

## 4. Authoritative Input Boundary

The existing `BootstrapPlan` is authoritative. Dry-run preview must not:

- reconstruct or silently re-plan bootstrap intent;
- reorder plan steps using an independent policy;
- mutate the plan or its steps;
- resolve a second set of generator identities;
- introduce an alternative planning model.

``` text
Input BootstrapPlan --- Immutable / Authoritative
```

## 5. Deterministic Preview Semantics

Equivalent accepted plans must produce equivalent previews.

Determinism requires:

- plan step order is preserved;
- expected-effect order is preserved;
- preview field ordering is stable;
- repeated preview of the same plan is reproducible;
- no timestamps, random identifiers, environment-dependent ordering, or
  incidental filesystem state enter preview equality.

``` text
Preview Ordering --- Deterministic
Equivalent Preview Behavior --- Required
```

## 6. Expected-effect Projection

Expected effects remain descriptive data only. Preview may report intended
create, update, delete, directory, or artifact effects already represented by
the plan, but it must not translate them into executable mutation commands.

Preview does not promise that a later apply operation will succeed. Apply-time
validation and mutation semantics remain separate future contracts.

## 7. Side-effect Boundary

``` text
Generator Instantiation --- Forbidden
Generator Execution --- Forbidden
Filesystem Mutation --- Forbidden
Manifest / Backup / Checkpoint Writes --- Forbidden
Network Access --- Forbidden
Plugin Activation --- Forbidden
```

Preview must be safe to repeat and safe to discard.

## 8. Failure Semantics

Preview is fail closed. An invalid or unsupported plan fails before a success
preview is returned.

Failure must produce:

- no generator construction or execution;
- no filesystem, manifest, backup, or checkpoint writes;
- no persisted preview artifact;
- no partially committed state;
- no success-shaped partial preview.

``` text
Failure Partial State --- Forbidden
```

This zero-partial-state rule does not introduce generalized rollback because
preview never commits state.

## 9. Explicit Non-goals

``` text
apply execution --- Not Started
validation runtime --- Not Started
checkpoint / resume --- Deferred
generalized rollback --- Deferred
CLI Boundary --- Not Accepted
Production Implementation --- Not Started
v1.2.3 Acceptance --- Accepted
```

No stable CLI flags, output schema, serialized preview format, plan hash, or
public SDK expansion is accepted by this design.

## 10. Test Strategy

Executable design contracts must prove:

- the accepted/implemented v1.2.2 planning core is the predecessor;
- all three proposed dry-run contracts are explicit;
- `BootstrapPlan` remains immutable and authoritative;
- preview ordering and equivalent-preview behavior are deterministic;
- expected effects remain descriptive data only;
- generator instantiation and execution are forbidden;
- all persistent writes, network access, and plugin activation are forbidden;
- failure is fail closed with zero partial state;
- apply, validation, checkpoint/resume, rollback, and CLI surfaces stay closed;
- production implementation and acceptance remain pending.

## 12. Code Review Checklist

### Architecture

- [ ] existing `BootstrapPlan` remains authoritative;
- [ ] no second planner, registry, lifecycle, or mutation pipeline is added;
- [ ] preview contracts are immutable and inspectable;
- [ ] plan and expected-effect ordering are preserved.

### Side effects and failure

- [ ] generators are neither instantiated nor executed;
- [ ] filesystem, manifest, backup, and checkpoint writes are forbidden;
- [ ] network access and plugin activation are forbidden;
- [ ] failure exposes no success-shaped partial preview or persisted state.

### Determinism

- [ ] repeated preview is reproducible;
- [ ] equivalent accepted plans produce equivalent previews;
- [ ] timestamps, random IDs, and incidental environment state are excluded.

### Scope and governance

- [ ] apply and validation runtime remain Not Started;
- [ ] checkpoint/resume and generalized rollback remain Deferred;
- [ ] Stable CLI syntax remains Not Accepted;
- [ ] no production implementation is introduced;
- [ ] roadmap, HISTORY, CHANGELOG, architecture, and tests agree.
